# 快速开始

[文档目录](README.md) · 下一步：[文献库与阅读](user-guide/library-and-reader.md)

完成本页后，你应能打开一篇 PDF、核对版面、配置一个模型，并完成一次选区翻译或问答。本页说明从源码运行；仓库文档不假设已有公开安装包或自动更新服务。

## 准备环境

| 场景                 | 需要                                                   |
| -------------------- | ------------------------------------------------------ |
| 浏览器预览、插件打包 | 推荐 Node.js 24.x 与 npm；本次文档验证环境为 24.15.0   |
| Tauri 桌面开发与打包 | 上述工具，加 Rust、Cargo 和目标平台的 Tauri 2 系统依赖 |
| 页面版面分析         | 仓库固定版本的 Heron ONNX 权重，约 171 MB              |
| 翻译和问答           | 已配置且可访问的模型服务                               |
| 复杂公式远端 OCR     | 独立 OCR 配置，或支持图片的回退模型                    |

模型准备脚本用 Node 直接执行 TypeScript，需要默认类型剥离支持。Node 22 系列至少使用 22.18.0；参见 [Node 官方 TypeScript 说明](https://nodejs.org/api/typescript.html#type-stripping)。Vite 本身允许 Node 20.19.0 或至少 22.12.0，但这不是本仓库所有脚本的环境要求。

平台系统包请按 [Tauri 官方前置条件](https://v2.tauri.app/start/prerequisites/)安装；不要把某一 Linux 发行版的包名当作所有平台的要求。

## 运行桌面版

在仓库根执行：

```sh
npm ci
npm run models:prepare
npm run tauri dev
```

`npm ci` 使用锁文件安装依赖。`models:prepare` 下载固定提交的权重，校验大小和 SHA-256；已有合格文件时直接复用。`tauri dev` 启动 Vite 和桌面窗口。模型准备不需要 API Key。

## 运行浏览器预览

```sh
npm ci
npm run models:prepare
npm run dev
```

打开终端显示的地址，默认 `http://127.0.0.1:1420`。浏览器和桌面使用同一分析逻辑，但文献、聊天、凭据与安装插件不会自动在两个环境间同步。预览适合检查界面和插件；模型服务还需允许该 origin 的 CORS 请求。

## 第一次阅读

1. 导入一篇含可提取文字的 PDF。文献库显示首页预览，重复的相同文件内容使用同一文档身份。
2. 打开论文，滚轮连续浏览。缩略图、PDF 原有目录和页码按钮用于跳转。
3. 等待当前页版面分析完成，用“版面”开关核对文字、图、表和公式的检测范围。其他页可在后台继续分析。
4. 通过“设置 → 通用设置”选择简体中文或英文。界面语言不会改变 PDF 原文、已有消息或翻译目标语言。

纯扫描页目前不会自动生成全文 OCR 文字。打开成功不意味着其中每一块内容已经可翻译；见[排查指南](user-guide/troubleshooting.md)。

## 第一次翻译或问答

1. 打开“设置 → 模型服务”，添加服务商、API 基础地址、需要的密钥及模型 ID，保存配置。
2. 返回阅读器，在聊天输入框旁的模型菜单选择已经添加的模型。模型图像能力要逐个配置，不能仅由名称推断。
3. 用蓝色框完整包住一个段落。确认段落出现紫色半透明覆盖框，再点击“翻译选区”。没有命中完整单元时不会显示这个动作。
4. 在结果窗口对照原 PDF、复建原文与译文，特别核对公式。需要复杂公式识别时再配置[独立 OCR](user-guide/models-and-ocr.md#选择公式-ocr)。
5. 在本体问答栏输入问题，例如“这一页中作者采用了什么控制方法？请标注依据页码”。回答基于文字检索和上下文，页码与结论仍需核对。

## 第一次安装插件

打开“设置 → 插件 → 从插件包安装”，选择可信的 `.cachx` 或 ZIP 包。缺少依赖时补充相应包，确认版本与权限后安装。安装和更新不重启软件；需要恢复插件时使用“重启插件”或“重启插件宿主”。详见[插件管理](user-guide/extensions.md)。

开发者可先打包仓库示例：

```sh
npm run extension:pack -- examples/reader-tools /tmp/example.reader-tools.cachx
```

示例在阅读器打开后激活，显示阅读背景、树侧栏和状态项。Windows 可将输出参数改为自己可写的绝对路径。

## 构建与进一步开发

```sh
npm run build
npm run tauri build -- --debug --no-bundle
```

`build` 先离线检查权重，再检查 TypeScript 并生成 `dist/`。桌面构建还需要目标平台依赖；`--no-bundle` 用于验证可执行程序，不生成系统安装包。生产浏览器预览使用 `npm run preview`。
