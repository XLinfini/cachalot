# 界面多语言维护

界面采用 [i18next](https://www.i18next.com/) 和 [react-i18next](https://react.i18next.com/guides/quick-start)，目前支持简体中文和英语。两份词典随应用打包，不需要联网或 API Key。

## 使用与语言偏好

到「设置 → 通用设置 → 界面语言」选择语言，保存后立即生效。首次使用默认简体中文；再次启动会先恢复语言，再挂载 React 界面。

偏好使用现有 `services.settings` 接口，键为 `uiLanguage`，值为 `zh` 或 `en`。桌面保存在 SQLite，浏览器预览保存在 localStorage。无效或缺失的值回退到中文；保存失败时保留当前语言并显示错误。

界面语言覆盖页面、按钮、提示、确认框、无障碍标签、解析进度、版面标签、已知应用错误，以及日期和数量形式。PDF 原文、文献标题、服务商名称、用户消息和已保存的回答是用户内容，保持原文。翻译目标语言由翻译提示词控制；问答当前仍使用应用层的中文回答要求，这些模型指令独立于界面语言。

## 文件与分层

| 文件 | 职责 |
| --- | --- |
| `src/i18n/locales/en.ts`、`zh.ts` | 本体界面与公共控件文案 |
| `src/extensions/selection-translation/locales.ts` | 选区翻译插件自己的中英文界面文案 |
| `src/i18n/index.ts` | i18next 初始化、语言持久化、日期 locale 和 HTML `lang` 同步 |
| `src/domain/messages.ts` | 无语言依赖的消息代码和参数编码 |
| `src/i18n/messages.ts` | 将应用消息、旧版缓存提示和已知 Tauri 字符串错误转换为当前语言 |
| `src/components/ProviderSettings.tsx` | 语言选择入口 |

React 使用 `useTranslation()`，业务服务和 Worker 不导入 React 或 i18next。服务通过 `message(code, values)` 返回语言无关的字符串编码，便于复用现有 Worker 和缓存契约。显示时调用 `localizeMessage()`，因此切换语言不需要重新解析 PDF。

旧缓存中的中文核对提示，以及当前 Rust 端的字符串错误，由显示层根据中文词典模板识别。若修改 Rust 的已知错误文案，需同步 `nativeErrors` 中的模板。第三方服务返回的诊断细节保留原文。

## 添加文案

```tsx
const { t } = useTranslation();
<button>{t("common.save")}</button>
<span>{t("common.pages", { count: document.pageCount })}</span>
```

- 同时补充中英文词典。英语定义文案键结构，中文使用 `satisfies LocaleResource` 检查缺失和多余的键；组件中的键有 TypeScript 检查。
- 完整句子放进词典，通过 `{{page}}`、`{{title}}` 等具名插值传值；数量使用 `count`，英语的 `_one`、`_other` 形式由 i18next 选择。
- 不要把即时翻译结果存入长期视图状态。提示状态保留消息代码，在渲染时转换；用户撰写的内容按原文保存。
- 新的服务提示先在 `MESSAGE_CODES` 中加入代码，再补齐两份词典的 `messages` 分组。
- 日期通过 `dateLocale()` 交给 `Intl` 格式化，避免在组件内固定 `zh-CN`。
- 按钮、输入框的布局继续遵循 [Tailwind 样式维护指南](styles.md)。较长的英语文案需检查横屏布局。

## 验证

```bash
npm run test:i18n
npm run format:check
npm run build
npm run test:styles -- /absolute/path/reference.pdf
```

`test:i18n` 检查文案键、插值一致性、英语数量形式、消息代码和旧缓存/Rust 错误转换。浏览器测试在两种横屏尺寸下分别检查两种语言，验证设置切换、语言恢复、草稿保留、连续阅读、文字选择与翻译、模型上拉菜单、图片上传/切换保护与公式来源重排。无需先运行 `test:paper`；真实论文分析按需缓存。

中文截图位于 `test-results/styles-after/`，英文截图位于 `test-results/styles-en/`，测量汇总位于前者的 `measurements.json`。测试使用独立上下文和模拟模型接口，不修改用户正在使用的文献库。

新增多语言测试及运行命令的统一约定见 [测试维护指南](../tests/README.md)。

## 插件文案

插件通过 `context.localization.registerResources({zh, en})` 注册自己的词典，命名空间固定为插件 ID。宿主在停用或激活失败时移除该词典，语言订阅也随作用域释放。本体词典不导入插件词典。需要通用按钮时，`translate` 对缺失键回退到本体公共词典。

React 插件使用 `useExtensionTranslation(context)`，其他实现使用 `context.localization.language/translate/onDidChangeLanguage`。清单、工具、动作、树节点和状态项使用 `{zh, en}` 标签，由工作台在渲染时选取，语言变化无需重新激活插件。选区翻译的提示词是插件配置，界面语言仍不改变翻译目标语言。共享公式渲染控件使用本体 `formulas` 文案，不依赖翻译插件。

`unit/i18n.test.ts` 同时检查本体与翻译插件的词典键和插值；浏览器夹具 `tests/fixtures/locales.ts` 只为测试组合两套文案，不参与生产依赖。
