# 插件交互设计约定

[插件开发](../extensions.md) · 相关：[视图](views.md)、[阅读交互](documents-and-reader.md)

插件应让读者继续理解原论文，清楚知道某次操作使用了哪些内容、在哪里产生结果，以及如何停止。下面是针对当前横屏阅读器的设计约定。

## 为任务选择 UI

| 用户任务                     | 优先选用                |
| ---------------------------- | ----------------------- |
| 跳转、书签、结构导航         | 树侧栏与命令            |
| 正文旁的说明、术语或辅助阅读 | 侧栏                    |
| 多行结果、记录、核对信息     | 底部 panel              |
| 用户发起的一次处理结果       | modal；关闭绑定请求取消 |
| 插件配置                     | settings 视图           |
| 简短状态或动作               | statusbar               |

背景和覆盖框用于辅助阅读，不能遮住原字或冒充原论文内容。避免为一个简单列表引入复杂 Webview。

## 阅读与选择

- 保留宿主蓝色手势框，自己的命中覆盖框让读者区分实际处理单元。
- 实际输出范围应与可见选取一致；更广上下文不能自动扩大处理范围。
- 异步页面或模型结果检查 documentId、来源版本、revision 与取消信号。
- 不抢占用户已选择的工具，不擅自跳页或打开无关 modal。
- 用户关闭视图或停用插件后，不让旧请求结果重新弹回界面。

## 双语与可访问操作

清单、树、工具、状态标签优先使用 `{zh, en}`。切换语言不需要重启插件，语言事件每个监听器独立触发。Webview 由插件负责翻译、标签和键盘交互；宿主不会自动翻译 HTML。

按钮使用可理解的动作名称；状态与错误保持可读，操作不可用时说明原因。支持横屏工作区，不靠不断扩大侧栏占满正文。长摘要进入视图，不挤进状态栏。

## 模型、数据与失败反馈

明确解释何时使用模型以及处理什么文字。悬停先命中、缓存、取消，不无条件连续产生收费请求。失败时保留来源和操作上下文，让用户选择重试；不要把后台重试和收费服务切换隐藏起来。

模型输出与论文文字按数据呈现，用转义或 textContent；不将它们拼接成脚本、指令或权限声明。权限说明与清单保持一致，reader.interact 的语义回调也会包含文档内容。

## 安装与重启

首次安装或更新最多涉及插件重载。不得要求本体重新启动、刷新窗口或销毁本体阅读/聊天状态。插件自己的状态应按业务成功时保存，作用域释放后能恢复，不依赖长时间 deactivate 收尾。

发布前按[打包验证表](packaging.md#测试和发布检查)检查中英文、停用、重启、依赖和无结果状态。当前支持的 UI 不等于 VS Code 的所有贡献点，不能在文档或安装说明中承诺未实现能力。
