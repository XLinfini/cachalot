# 模型与公式 OCR

[文档目录](../README.md) · 相关：[翻译](translation.md)、[问答](chat.md)、[排查](troubleshooting.md)

## 三种能力的区别

| 能力         | 运行位置与配置                                      |
| ------------ | --------------------------------------------------- |
| 页面版面分析 | 本地固定 Heron 权重，不需要 API Key                 |
| 翻译和问答   | 在“设置 → 模型服务”配置 OpenAI Chat 兼容服务        |
| 复杂公式识别 | 在“设置 → 公式 OCR”选择独立模型，或使用图像模型回退 |

独立 OCR 不会把聊天模型切换成 OCR 模型。专用 OCR 的模型列表不会混入聊天和翻译菜单。

## 打开设置

点击“设置”，或按 Ctrl+,（macOS 为 Cmd+,），在当前工作区上方打开亮色设置浮窗。顶部搜索按分类名称和设置关键词筛选，左侧可切换通用、模型服务、公式 OCR、缓存及插件设置。右上角可放大或还原窗口。

点击右上角关闭按钮或按 Esc 返回原来的文献库或阅读器；搜索框有文字时，首次 Esc 清空搜索。阅读位置、聊天草稿和正在等待的问答保持。栏目和界面语言切换保留模型服务与插件设置的未保存草稿；关闭整个窗口前请保存需要保留的配置。缓存确认和模型目录打开时，Esc 先关闭最上层窗口。

## 添加语言模型

1. 添加服务商，填写显示名称、API 基础地址和必要的密钥。
2. 获取临时可选模型列表，或手填准确的模型 ID。
3. 添加需要使用的模型，逐个配置图像能力，保存。
4. 回到阅读器选择已添加的模型。

获取 `/models` 列表、保存设置和成功生成回答是不同的验证边界；部分服务不提供模型目录，但仍可以手工配置模型。图像能力勾选是显式配置，不能使一个实际文字模型获得图像能力。

## API 地址如何解释

界面显示实际请求地址供核对。通用 Chat 请求使用 `/chat/completions`，模型目录使用 `/models`。

| 填写的基础地址                                | 通用 Chat 请求地址                                    |
| --------------------------------------------- | ----------------------------------------------------- |
| `https://api.example.com`                     | `https://api.example.com/v1/chat/completions`         |
| `https://api.example.com/v1`                  | `https://api.example.com/v1/chat/completions`         |
| `https://api.example.com/custom/api`          | `https://api.example.com/custom/api/chat/completions` |
| `https://api.example.com/v1/chat/completions` | 先还原基础路径，再生成同一 Chat 地址                  |

这些域名仅为说明规则。已有基础路径不额外插入 `/v1`；查询参数保留，fragment 移除。专用 OCR 使用自己的协议地址，不能把此表套用到所有厂商接口。

## 密钥编辑与保存

已保存密钥默认显示遮罩，点击眼睛才显示完整值。输入新的值才替换已有密钥；留空保存保留现有值。切换服务商、保存或离开设置会恢复隐藏。

桌面密钥放在操作系统密钥库；浏览器使用当前 origin 的 IndexedDB 与 Web Crypto 加密存储，保存失败会报错。浏览器同源代码仍可使用该密钥，其隔离能力不同于系统密钥库。更换域名、端口、浏览器 profile 或清除站点数据不会自动迁移配置。

## 选择公式 OCR

| 设置模式                         | 行为                                                          |
| -------------------------------- | ------------------------------------------------------------- |
| 使用当前翻译模型（需要支持图像） | 没有独立选择时使用调用方的图像模型；文字模型保留原图          |
| 使用独立的 OCR 模型              | 只用明确选中的 OCR 模型；配置失效时报告问题，不自动换收费服务 |
| 不进行远端识别，保留公式原图     | 关闭远端公式请求；原生简单公式仍可直接恢复                    |

1. 打开“设置 → 公式 OCR”。可以添加 GLM-OCR 预设，也可以配置现有支持的接口。
2. 添加专用 OCR 模型时，确认准确的接口类型与模型 ID。
3. 选择“使用独立的 OCR 模型”，展开服务商并选择已添加的模型；选择自动保存。
4. 翻译仍选择普通语言模型，公式由独立 OCR 准备后再参与翻译核对。

当前内置接口：

| 接口                                 | 适用情况                                             |
| ------------------------------------ | ---------------------------------------------------- |
| GLM 专用版面接口（`glm-layout`）     | 官方 GLM-OCR JSON 协议；模型目录使用固定预设         |
| 专用公式 Chat 接口（`formula-chat`） | 支持固定 `Formula Recognition:` 任务的 Chat 兼容端点 |
| 多模态 LLM（`vision-llm`）           | 公式截图与原生字符证据，需要图像能力                 |

本仓库 GLM 预设地址为 `https://open.bigmodel.cn/api/paas/v4`、模型为 `glm-ocr`。具体账号使用的平台、区域与密钥应和实际接口配套；协议入口见 [GLM 官方 SDK](https://github.com/zai-org/GLM-OCR)及 [Z.AI 版面 API](https://docs.z.ai/api-reference/tools/layout-parsing)。

“检查连接”会向专用 OCR 发送本地生成的测试公式，属于模型请求，可能产生费用。不要把连接检查结果理解为论文中每个复杂公式都能正确识别。

## 失败与协议边界

请求失败会显示脱敏后的服务商错误正文和 request ID。HTTP 错误、业务错误、字符检查失败、模型缺少图像能力应分别处理；软件不凭模型名称自动切换收费服务。

未支持的私有协议不能只改模型 ID。新增协议是本体构建时的[OCR 适配器开发](../../src/infrastructure/ocr/providers/README.md)，当前社区插件没有注册任意 OCR 厂商的运行时接口。
